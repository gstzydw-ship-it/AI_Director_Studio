# Failure Mode：动作断档

## 定义

动作断档指上一镜已经建立的身体、道具或门状态，到了下一镜没有按物理顺序继续，而是重复、跳过、回弹或换成另一个状态。

它常发生在跨镜动作、子分镜、门口戏、电梯戏、桌面道具和身体接触中。

## 典型症状

- 上一镜手已经松开，下一镜又重新抓住。
- 上一镜脚已过门槛，下一镜又从门外起步。
- 门缝已经收窄，下一镜又无解释打开。
- 道具已递出，下一镜仍在原人手里。
- 撞上后应短促稳住，却被写成贴身拥抱或慢动作凝视。
- 动作完成后才切，下一镜只能补拍结果，节奏变钝。

## 根因

常见根因：

- 没有 `state_chain`。
- `cut_point` 写成抽象词，没有绑定动作中段。
- 子分镜没有 `parent_shot_id`，成了漂浮镜头。
- 只继承人物身份，没有继承身体部位和道具状态。
- 为了情绪特写吞掉了动作推进时间。

## 识别清单

检查每个跨镜动作：

- 上一镜尾帧中，身体部位处于什么状态。
- 下一镜首帧是否从同一状态继续。
- 动作是否被重复开始。
- 物体状态是否单向推进。
- 切点是否在动作 50%-70% 的未完成状态。
- 如果切到特写，特写是否承接前镜动作逻辑。

## 最小修复顺序

1. 补 `state_chain`，把状态写成单向链。
2. 把抽象 `cut_point` 改成具体动作锚点。
3. 给子镜头补 `parent_shot_id`，挂到已有主镜头。
4. 若动作被重复，删掉重复起点或改为继续状态。
5. 若特写吞掉动作，把特写缩短为子分镜或降级为中近景。
6. 若尾帧无法续接，最后 0.5-1 秒回到关系景或明确可继承状态。

## 高风险对象

- 门、电梯门、车门、闸门。
- 手、手腕、手臂、肩线。
- 脚步、门槛、站位。
- 手机、文件、照片、杯子、合同。
- 身体接触、扶稳、推开、阻拦。
- 群体聚散和让路。

## 修复示例

问题：

```yaml
S01: 她推门进入。
S02-a: 手部特写，门把被按下。
state_delta: 情绪更紧张。
```

最小修复：

```yaml
S01:
  state_delta: 她的右脚跨过门槛，身体进入门内，门仍半开。
S02-a:
  parent_shot_id: S01
  trigger: 门状态需要从半开推进到继续合拢
  cut_point: 她手指刚离开门把、动作完成约 60% 时
  action_phase: mid_action
  duration_hint: 0.6s
  state_delta: 门把回弹，门从半开继续合拢
```

## 不要这样修

- 不要重写整组镜头。
- 不要新增剧本外动作解释断档。
- 不要把动作断档用心理描写糊过去。
- 不要让下一镜从动作起点重做。
- 不要用大头特写遮掉所有状态问题。

## 通过标准

修复后，读者只看 `state_chain`、`cut_point` 和尾帧合同，就能判断动作如何从上一镜尾帧延续到下一镜首帧。
