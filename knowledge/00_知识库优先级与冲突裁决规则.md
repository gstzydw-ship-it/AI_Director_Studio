# 00_知识库优先级与冲突裁决规则

用途：为多 Agent 导演团队提供统一的规则优先级、职责边界和冲突裁决方式。所有 Agent 在读取各自专业知识前，必须先遵守本文件。

---

## 一、总原则

知识库不是百科全文注入，而是按当前 Agent、当前阶段、当前任务选择最小且高信号的规则集合。

当多条规则同时命中且出现强弱不一致时，必须按本文件优先级裁决，不得把所有规则机械叠加。

---

## 二、规则优先级

### P0：用户显式要求与安全边界
- 用户在当前任务中的明确要求优先。
- 私密、暴力、身体观看等安全边界优先。
- 若用户要求与安全边界冲突，以安全边界为准。

### P1：连续性与模型可生成性
优先文件：
- `06_连续性与安全规则.md`
- `07_Seedance输出词典与模型适配.md`
- `18_情绪锚点与逐段交互与仰拍限制补丁.md`

裁决原则：
- 人物位置、轴线、道具、动作接续、尾帧继承不能被美学规则破坏。
- 模型稳定性规则优先于复杂镜头设计。
- 仰拍、俯拍、手持晃动、快速运镜必须服从生成稳定性和片段限制。

### P2：片段边界与主分镜合法性
优先文件：
- `03_镜头切换与推进规则.md`
- `05_剧本拆分与15秒片段规划规则.md`

裁决原则：
- 片段边界、主分镜/子分镜层级、完整发言单元不被镜头美学反向改写。
- 不得为了多机位或特写数量强拆完整动作段。

### P3：故事节奏与剧本层改写
优先文件：
- `09_节奏总控与剧本改写规则.md`
- `15_故事节奏控制规则.md`

裁决原则：
- 节奏总控只改写动作层和氛围层，不改事件层和台词层。
- `atmosphere_strategy` 是给镜头导演的建议，不是镜头硬指令。

### P4：镜头调用、多机位与视觉风格
优先文件：
- `20_镜头库与机位库.md`
- `21_镜头调用规则与多机位模板.md`
- `22_多机位分镜与镜头多样性规则.md`

裁决原则：
- 镜头美学必须服从 P1-P3。
- 多机位模板在 AI 视频生成中应优先服务 15 秒导演片段内部的主分镜/子分镜组织；子分镜用于补足脚步、手部、道具、视线、关系或反应锚点，最终 prompt 必须使用单层时间轴顺序排列。
- 权力、焦点、景别、反拍等规则只在适用场景成立时调用。

### P5：范例、案例与源材料
优先文件：
- `19_Gold_Standard_Prompt范例.md`
- `23_视频教学提取_全场景分镜与转场库.md`
- `测试提取_*.md`

裁决原则：
- 范例只提供写法参考，不覆盖硬规则。
- 源材料只用于人工复盘和后续提炼，不参与默认运行时检索。
- 源材料中的“必须”“禁止”“全片”等强表达，必须经过去重、降噪、归属和例外条件处理后，才能进入正式规则库。

## 三、常见冲突裁决

### 1. 权力仰拍 vs 仰拍限制
若 `21` 建议权力压制使用仰拍，但 `18` 的仰拍限额或禁用场景已触发，必须以 `18` 为准。  
替代做法：用画面占比、边缘挤压、前景遮挡、景别差异、站位高度和中心构图表达权力。

### 2. 多机位同步拍 vs 单层时间轴子分镜
`21` 中的“必须同步拍”是实拍语境，不能直接下放为无边界硬切。  
在 AI 生成语境中，必须解释为：一个 15 秒导演片段可以围绕同一动作锚点规划多个主分镜/子分镜；子分镜必须在同一条时间轴上拥有独立时间段。  
裁决标准是：允许 `0-3秒 主分镜1`、`3-5秒 子分镜1.1`、`5-8秒 主分镜2`；禁止写外层动作单元 + 内层子时间轴，也禁止在没有主/子分镜边界的句子里连续写“切至/硬切/反打/转到另一个机位”。相邻分镜不得相同景别直切，例如特写不能直接接特写。

### 3. 反应镜头时长口径
剪辑遮挡型反应镜头可短至 1-1.5 秒。  
剧情受击、信息炸点、反转承接型反应镜头必须遵守 `15` 的底线：至少 1.5 秒，通常 1.5-2.5 秒。

### 4. 快节奏 vs 三快叠加
若需要快节奏，只能让主体动作、镜头运动、环境复杂度中的一个维度变快。  
不得用“短剧节奏快”作为三快叠加的理由。

### 5. 景别收缩 vs 竖屏特写限频
`21` 的景别收缩规则必须服从 `02` 与 `18` 的竖屏特写限频和情绪锚点精度。  
若 CU 已达到限额，优先改用半身景、局部特写或姿态变化承接情绪。

## 四、Agent 职责边界

### scene_analyst
负责提取场景、人物、关系、空间和导演意图。不得拆片，不得改写剧本，不得直接下最终镜头指令。

### rhythm_rewrite_director
负责动作层和氛围层改写、节奏阶段标注、atmosphere_strategy。不得改台词，不得新增事件，不得强制指定镜头。

### story_planner
负责 15 秒片段、主分镜骨架、完整发言单元和动作段边界。不得为了镜头美学改写剧本内容。

### shot_director
负责镜头、景别、机位、反拍、转场和多机位规划。必须继承上游片段骨架，不得重拆片，不得改台词。

### prompt_compiler
负责把已确定的分镜编译为 Seedance 可执行 prompt。不得新增剧情，不得重新发明镜头逻辑。

### quality_inspector
负责检查冲突、遗漏、连续性、模型风险和输出可执行性。可以指出问题，不直接重写上游职责范围外的内容。

---

## 五、执行要求

1. 任何 Agent 发现规则冲突时，先按本文件裁决，再执行本 Agent 的专业规则。
2. 若专业规则没有明确适用场景，不得把它扩展成全局默认。
3. 若源材料与正式规则冲突，以正式规则为准。
4. 若正式规则之间冲突，以更高优先级文件为准。
5. 若同优先级规则冲突，以更具体、条件更明确、离当前任务更近的规则为准。

---

## 六、一句话总纲
**先守安全、连续性和可生成性，再守片段结构和节奏，最后调用镜头美学；源材料不能直接压过正式规则，多 Agent 各守边界，不把所有规则机械叠加。**

---

## 七、规则注册表使用方式

`rule_registry.yaml` 是正式规则索引，不是新的创作规则正文。它用于回答四个问题：这条规则归哪个 Agent 管、属于哪个优先级、在什么场景适用、遇到冲突时应回看哪些正式文件。

执行要求：
1. 若某条规则已进入 `rule_registry.yaml`，Agent 应按注册表中的 `owner_agent` 和 `priority` 确认职责边界，再读取对应 `source_files` 的正文细节。
2. 若 Markdown 正文里出现重复编号或重复标题，以注册表中的 `id` 作为跨文件唯一身份，不再用局部 `R-xxx` 编号做全局唯一判断。
3. 若原始材料、测试提取稿或案例库没有进入注册表，不得把其中的强指令直接当成运行时硬规则。
4. 若注册表与正文冲突，先按本文件优先级裁决，再人工修正注册表或正文，禁止让下游 Agent 自行猜测。
